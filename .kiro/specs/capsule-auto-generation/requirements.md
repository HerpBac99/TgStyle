# Requirements Document

## Introduction

Функция автоматической генерации капсул позволяет пользователям создавать стильные образы из вещей их гардероба с помощью AI (Gemini API). Система анализирует имеющиеся вещи с их полной классификацией (9 полей: category, subtype, color, material, fit, style, season, pattern, description), приоритизирует неиспользованные или любимые вещи, и генерирует 3 варианта капсул с рекомендациями. Пользователь может выбрать понравившийся вариант и сразу перейти к его редактированию в canvas-редакторе.

## Glossary

- **Capsule System**: Система управления капсулами (образами) в приложении TgStyle
- **Wardrobe System**: Система управления гардеробом пользователя
- **Gemini API**: Google Gemini API для генерации комбинаций одежды
- **Canvas Editor**: Редактор капсул на основе Fabric.js
- **Generation Modal**: Модальное окно с вариантами сгенерированных капсул
- **Stock Wardrobe**: Базовый набор стоковых изображений вещей для рекомендаций
- **Similarity Score**: Метрика схожести капсул (процент совпадающих вещей)
- **WardrobeItem**: Элемент гардероба с 9 полями классификации: category, subtype, color, material, fit, style, season, pattern, description
- **Generate Button**: Кнопка "Сгенерировать" в стиле liquid glass
- **Usage Count**: Количество капсул, в которых используется конкретная вещь
- **Unused Items**: Вещи с usageCount = 0 (еще не использованные в капсулах)
- **Rarely Used Items**: Вещи с usageCount 1-3 (одобрены пользователем, но используются редко)
- **Popular Items**: Вещи с usageCount >= 3 (часто используемые, любимые)
- **AI Recommendations**: Стилистические рекомендации от Gemini API по улучшению образа
- **Current Season**: Текущий сезон определяемый по месяцу (winter, spring, summer, autumn)
- **Layering**: Многослойность одежды (базовый слой, средний слой, верхний слой)

## Requirements

### Requirement 1

**User Story:** Как пользователь, я хочу видеть кнопку генерации капсул на вкладке Capsules, чтобы быстро создавать новые образы

#### Acceptance Criteria

1. WHEN пользователь открывает вкладку Capsules, THE Capsule System SHALL отображать кнопку "Сгенерировать" поверх грида с капсулами
2. THE Generate Button SHALL иметь стиль liquid glass (полупрозрачный фон, размытие, соответствие цветовой схеме приложения)
3. THE Generate Button SHALL быть позиционирована внизу экрана с фиксированным положением поверх грида капсул
4. WHEN пользователь нажимает на кнопку, THE Generate Button SHALL показывать визуальную обратную связь (active state с изменением прозрачности)

### Requirement 2

**User Story:** Как пользователь, я хочу получать 3 варианта сгенерированных капсул на основе неиспользованных или любимых вещей, чтобы выбрать наиболее подходящий образ

#### Acceptance Criteria

1. WHEN пользователь нажимает кнопку "Сгенерировать", THE Capsule System SHALL загрузить все вещи гардероба пользователя с полными данными (9 полей классификации)
2. THE Capsule System SHALL загрузить все существующие капсулы пользователя для анализа использования вещей
3. THE Capsule System SHALL вычислить статистику использования для каждой вещи (количество капсул, в которых она используется)
4. THE Capsule System SHALL создать два списка: unused_items (неиспользованные вещи) и favorite_items (вещи используемые в 3+ капсулах)
5. THE Capsule System SHALL приоритизировать unused_items при формировании запроса к Gemini API
6. THE Capsule System SHALL сформировать JSON с полными данными о каждой вещи: {id, category, subtype, color, material, fit, style, season, pattern, description, usageCount}
7. THE Capsule System SHALL отправить запрос к Gemini API с приоритизированным списком вещей и инструкцией создать 3 стильных комбинации
8. THE Capsule System SHALL получить от Gemini API 3 различных комбинации вещей с названиями, описаниями и рекомендациями
9. WHILE генерация выполняется, THE Capsule System SHALL отображать индикатор загрузки с текстом "Создаем образы для вас..."
10. WHEN генерация завершена, THE Capsule System SHALL открыть Generation Modal с 3 вариантами капсул

### Requirement 3

**User Story:** Как пользователь, я хочу видеть превью сгенерированных капсул в модальном окне, чтобы оценить варианты перед выбором

#### Acceptance Criteria

1. THE Generation Modal SHALL отображать 3 варианта капсул в виде кликабельных превью-изображений
2. THE Generation Modal SHALL показывать под каждым превью краткое описание образа от Gemini API
3. WHEN пользователь нажимает на превью капсулы, THE Capsule System SHALL открыть Canvas Editor с этой капсулой
4. THE Generation Modal SHALL содержать кнопку "Сгенерировать заново" для повторной генерации
5. THE Generation Modal SHALL содержать кнопку "Отмена" для закрытия окна без выбора
6. THE Generation Modal SHALL иметь полупрозрачный overlay-фон, затемняющий основной контент

### Requirement 4

**User Story:** Как пользователь, я хочу сразу перейти к редактированию выбранной капсулы, чтобы настроить образ под себя

#### Acceptance Criteria

1. WHEN пользователь нажимает на превью капсулы, THE Capsule System SHALL создать новую капсулу в базе данных
2. THE Capsule System SHALL сохранить выбранную комбинацию вещей в поле canvasData капсулы
3. THE Capsule System SHALL закрыть Generation Modal
4. THE Capsule System SHALL открыть Canvas Editor с загруженной капсулой для редактирования
5. THE Canvas Editor SHALL отобразить все вещи выбранной капсулы на canvas с автоматическим позиционированием

### Requirement 5

**User Story:** Как пользователь, я хочу чтобы система не создавала дубликаты существующих капсул, чтобы мой гардероб оставался организованным

#### Acceptance Criteria

1. BEFORE генерации новых капсул, THE Capsule System SHALL загрузить все существующие капсулы пользователя
2. THE Capsule System SHALL вычислить Similarity Score между каждой сгенерированной капсулой и существующими капсулами
3. IF Similarity Score равен 100%, THEN THE Capsule System SHALL отклонить эту комбинацию и запросить альтернативу у Gemini API
4. IF Similarity Score больше 80%, THEN THE Capsule System SHALL показать предупреждение "Похожая капсула уже существует" под превью
5. THE Capsule System SHALL разрешить создание капсулы с Similarity Score менее 80%

### Requirement 6

**User Story:** Как пользователь, я хочу получать рекомендации недостающих вещей и аксессуаров, чтобы дополнить свой гардероб

#### Acceptance Criteria

1. THE Capsule System SHALL передавать Gemini API инструкцию приоритизировать вещи из гардероба пользователя
2. WHERE у пользователя недостаточно базовых вещей (обувь, верхняя одежда), THE Capsule System SHALL использовать Stock Wardrobe для дополнения образа
3. WHERE у пользователя достаточно вещей для полноценного образа, THE Capsule System SHALL рекомендовать аксессуары (очки, серьги, цепочки, сумки, ремни) из Stock Wardrobe
4. THE Capsule System SHALL отмечать рекомендованные вещи и аксессуары специальным индикатором "Рекомендация" на canvas
5. WHEN пользователь нажимает на рекомендованную вещь, THE Capsule System SHALL открыть ссылку на магазин (Lamoda или LimeStore)
6. THE Capsule System SHALL сохранять информацию о рекомендованных элементах в поле metadata капсулы

### Requirement 7

**User Story:** Как пользователь, я хочу чтобы система учитывала разное количество вещей в категориях, чтобы генерировать разнообразные образы

#### Acceptance Criteria

1. THE Capsule System SHALL анализировать количество вещей в каждой категории гардероба пользователя
2. WHEN генерирует 3 варианта капсул, THE Capsule System SHALL варьировать вещи из категорий с большим количеством элементов (кофты, футболки)
3. THE Capsule System SHALL разрешать повторение вещей из категорий с малым количеством элементов (обувь, верхняя одежда) между вариантами
4. THE Capsule System SHALL обеспечивать минимум 30% различий между каждым из 3 вариантов капсул
5. THE Capsule System SHALL передавать Gemini API информацию о количестве вещей в каждой категории для оптимизации генерации

### Requirement 8

**User Story:** Как пользователь, я хочу иметь возможность перегенерировать варианты, если предложенные образы мне не подходят

#### Acceptance Criteria

1. WHEN пользователь нажимает кнопку "Сгенерировать заново" в Generation Modal, THE Capsule System SHALL закрыть текущее модальное окно
2. THE Capsule System SHALL выполнить новый запрос к Gemini API с указанием исключить предыдущие комбинации
3. THE Capsule System SHALL отобразить индикатор загрузки во время новой генерации
4. THE Capsule System SHALL открыть Generation Modal с новыми 3 вариантами капсул
5. THE Capsule System SHALL сохранять историю предыдущих генераций в рамках текущей сессии для избежания повторов

### Requirement 9

**User Story:** Как пользователь, я хочу чтобы система корректно обрабатывала ошибки генерации, чтобы понимать что происходит

#### Acceptance Criteria

1. IF Gemini API возвращает ошибку, THEN THE Capsule System SHALL отобразить уведомление "Не удалось сгенерировать капсулы. Попробуйте позже"
2. IF у пользователя менее 3 вещей в гардеробе, THEN THE Capsule System SHALL отобразить уведомление "Добавьте больше вещей в гардероб для генерации капсул"
3. IF достигнут лимит Gemini API, THEN THE Capsule System SHALL отобразить уведомление "Превышен дневной лимит генераций. Попробуйте завтра"
4. THE Capsule System SHALL логировать все ошибки генерации для отладки
5. WHEN происходит ошибка, THE Capsule System SHALL закрыть индикатор загрузки и вернуть пользователя на вкладку Capsules

### Requirement 10

**User Story:** Как пользователь, я хочу чтобы система умно приоритизировала вещи с учетом их использования, чтобы получать разнообразные и проверенные комбинации

#### Acceptance Criteria

1. WHEN пользователь нажимает кнопку "Сгенерировать", THE Capsule System SHALL автоматически вычислить usageCount для каждой вещи
2. THE Capsule System SHALL приоритизировать вещи с usageCount 1-3 (одобрены пользователем, но используются редко)
3. THE Capsule System SHALL передать Gemini API список вещей с указанием usageCount и инструкцию создать 3 разных подхода
4. THE Gemini API SHALL создать капсулу 1 как микс редко используемых (usageCount 1-2) и популярных вещей (usageCount 3+)
5. THE Gemini API SHALL создать капсулу 2 с большим количеством популярных вещей (проверенные комбинации)
6. THE Gemini API SHALL создать капсулу 3 как экспериментальную (может включать 1-2 новые вещи с usageCount = 0)
7. THE Capsule System SHALL включить в запрос все 9 полей классификации для каждой вещи

### Requirement 11

**User Story:** Как пользователь, я хочу получать стилистические рекомендации от AI для каждой капсулы, чтобы понимать почему эти вещи сочетаются

#### Acceptance Criteria

1. THE Capsule System SHALL запросить у Gemini API для каждой капсулы: название (максимум 3 слова), описание образа, обоснование выбора комбинации
2. THE Gemini API SHALL анализировать все 9 полей классификации вещей для создания гармоничных комбинаций
3. THE Gemini API SHALL учитывать сочетаемость цветов, стилей, материалов, сезонности и паттернов
4. THE Gemini API SHALL предоставлять рекомендации по улучшению образа (например: "Добавьте аксессуары для завершения образа")
5. THE Capsule System SHALL отображать рекомендации под превью каждой капсулы в модальном окне
6. THE Capsule System SHALL сохранять рекомендации в поле metadata капсулы для последующего просмотра

### Requirement 12

**User Story:** Как пользователь, я хочу чтобы система учитывала текущий сезон и многослойность одежды при генерации капсул, чтобы получать актуальные образы

#### Acceptance Criteria

1. WHEN пользователь нажимает кнопку "Сгенерировать", THE Capsule System SHALL определить текущий сезон на основе месяца (декабрь-февраль = winter, март-май = spring, июнь-август = summer, сентябрь-ноябрь = autumn)
2. THE Capsule System SHALL передать Gemini API информацию о текущем сезоне и месяце
3. THE Gemini API SHALL учитывать многослойность одежды при создании комбинаций (футболки/рубашки = базовый слой круглый год, свитера/кофты = средний слой или верхний в прохладную погоду, куртки/пальто = верхний слой в холодное время)
4. THE Gemini API SHALL создавать образы подходящие для текущего сезона с учетом возможности многослойности
5. THE Gemini API SHALL НЕ использовать жесткую фильтрацию по полю season, а учитывать контекст использования вещи
6. THE Capsule System SHALL передавать в промпт инструкции по многослойности для текущего сезона

### Requirement 13

**User Story:** Как пользователь, я хочу чтобы сгенерированные капсулы автоматически сохранялись с осмысленными названиями, чтобы легко их находить

#### Acceptance Criteria

1. WHEN пользователь выбирает вариант капсулы, THE Capsule System SHALL использовать название сгенерированное Gemini API (максимум 3 слова на русском)
2. THE Capsule System SHALL сохранить дату создания капсулы в поле createdAt
3. THE Capsule System SHALL сохранить источник создания "ai_generated" в поле metadata
4. THE Capsule System SHALL сохранить рекомендации от Gemini в поле metadata
5. THE Capsule System SHALL сохранить информацию о текущем сезоне в поле metadata
6. THE Capsule System SHALL добавить новую капсулу в начало списка капсул пользователя
