# План рефакторинга клиент-серверного взаимодействия TgStyle

## 🔴 Критические проблемы

### 1. **Дублирование HTTP клиентов**
- Используется и `api.ts` (extends ApiClient) и прямые `fetch()` вызовы
- 15+ модулей используют `fetch()` вместо централизованного `api`
- Нет единой обработки ошибок и логирования

### 2. **Несогласованность типов клиент-сервер**
- `userId` на клиенте хранит `telegramId` (string), а не реальный `userId` из БД
- Путаница между `photoPath` (имя файла) и полным путем к изображению
- `HistoryItem` interface не соответствует серверной модели данных

### 3. **Избыточные API запросы**
- При загрузке истории каждый элемент может требовать отдельный запрос для лайков
- Множественные запросы в `dataCache` для wardrobe/capsules
- Отсутствует батчинг и оптимизация

### 4. **Проблемы с авторизацией**
- `initData` передается в каждом запросе вручную
- Нет централизованного middleware для auth
- Дублирование валидации на сервере

## 🟡 Средние проблемы

### 5. **Неэффективное кэширование**
- localStorage используется как основное хранилище вместо кэша
- Нет инвалидации кэша при обновлениях
- Дублирование данных между localStorage и памятью

### 6. **Отсутствие оптимистичных обновлений**
- UI блокируется при каждом запросе
- Нет предварительного отображения изменений

### 7. **Мертвый код**
- Неиспользуемые методы в `historyManager`
- Legacy поля типа `photoData` в БД

## 📋 План рефакторинга

### Фаза 1: Унификация HTTP клиента
1. Рефакторить все `fetch()` вызовы на использование `api.ts`
2. Добавить interceptors для автоматической передачи `initData`
3. Централизованная обработка ошибок и retry логика

### Фаза 2: Исправление типов
1. Создать shared типы между клиентом и сервером
2. Исправить путаницу с `userId`/`telegramId`
3. Нормализовать пути к файлам

### Фаза 3: Оптимизация запросов
1. Внедрить GraphQL или батчинг для множественных запросов
2. Добавить server-side агрегацию для лайков/комментариев
3. Реализовать пагинацию и lazy loading

### Фаза 4: Улучшение кэширования
1. Внедрить React Query или SWR для управления состоянием
2. Реализовать оптимистичные обновления
3. Добавить Service Worker для offline режима

### Фаза 5: Очистка кода
1. Удалить мертвый код и legacy поля
2. Рефакторить дублирующиеся методы
3. Добавить unit тесты

- **-40%** размера bundle
- **+50%** скорости загрузки
- **100%** типобезопасность
