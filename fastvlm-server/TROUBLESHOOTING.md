# FastVLM Troubleshooting: План решения проблем с 7B моделью

## 🚨 Текущая проблема
1.5B модель работает, но 7B модель не загружается

## 📋 Пошаговый план диагностики

### Шаг 1: Полная диагностика системы
```bash
cd fastvlm-server
python diagnose.py
```

**Что это даёт**: Автоматически проверит все зависимости, модели и ресурсы системы.

### Шаг 2: Проверка доступных моделей
```bash
python switch_model.py
```

**Что это даёт**: Покажет какие модели установлены и их статус.

### Шаг 3: Минимальный тест загрузки
```bash
# Сначала протестируем рабочую модель
python test_min_load.py 1.5b

# Потом проблемную модель
python test_min_load.py 7b-int4
```

**Что это даёт**: Точно определит на каком этапе происходит сбой.

### Шаг 4: Выбор стратегии решения

## 🔧 Варианты решений (по приоритету)

### Решение A: Переключиться на 1.5B (БЫСТРО)
```bash
python switch_model.py 1.5b
python server.py
```
**Когда использовать**: Если нужно быстро запустить рабочий сервер

### Решение B: Принудительно CPU для 7B
```bash
export FASTVLM_DEVICE=cpu
export FASTVLM_MODEL=7b-int4
python test_min_load.py 7b-int4
```
**Когда использовать**: Если проблема в GPU памяти

### Решение C: Распаковать полную 7B модель
```bash
cd models
unzip llava-fastvithd_7b_stage3.zip
cd ..
python switch_model.py 7b-full
python test_min_load.py 7b
```
**Когда использовать**: Если int4 модель повреждена

### Решение D: Переустановить 7B модель
```bash
python download_7b_int4.py
python test_min_load.py 7b-int4
```
**Когда использовать**: Если файлы модели неполные

### Решение E: Обновить зависимости
```bash
pip install --upgrade torch transformers bitsandbytes accelerate
python test_min_load.py 7b-int4
```
**Когда использовать**: Если проблемы с квантизацией

## 🎯 Алгоритм выбора решения

1. **Запустить диагностику**: `python diagnose.py`
2. **Если показывает проблемы с зависимостями** → Решение E
3. **Если показывает проблемы с файлами модели** → Решение C или D
4. **Если показывает проблемы с GPU памятью** → Решение B
5. **Если всё равно не работает** → Решение A (fallback)

## 🔍 Что делать с результатами диагностики

### Типичные ошибки и решения:

#### `CUDA out of memory`
- **Решение**: Используйте CPU (`export FASTVLM_DEVICE=cpu`)
- **Или**: Переключитесь на 1.5B модель

#### `FileNotFoundError: model.safetensors`
- **Решение**: Переустановите модель (`python download_7b_int4.py`)
- **Или**: Распакуйте архив (`unzip llava-fastvithd_7b_stage3.zip`)

#### `ImportError: No module named 'bitsandbytes'`
- **Решение**: Установите зависимости (`pip install bitsandbytes`)

#### `Config file not found`
- **Решение**: Модель повреждена, переустановите

## 📝 Логирование проблем

Все скрипты автоматически логируют ошибки. Если проблема не решается:

1. Сохраните вывод диагностики:
```bash
python diagnose.py > diagnostics.txt 2>&1
```

2. Сохраните вывод теста загрузки:
```bash
python test_min_load.py 7b-int4 > test_results.txt 2>&1
```

3. Отправьте эти файлы для анализа
