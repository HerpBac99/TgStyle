# 📱 План реализации публичной ленты капсул (Instagram-style Feed)

## 🎯 Цель
Создать новую вкладку "Лента" с публичными капсулами всех пользователей в Instagram-подобном макете с чередующимися большими и маленькими элементами.

## 🏗️ Архитектурное решение

**Выбранный подход: CSS Grid + Intersection Observer**

### Преимущества:
1. **CSS Grid** - нативное, высокопроизводительное решение без внешних библиотек
2. **Простота поддержки** - чистый CSS без JS-вычислений позиций
3. **Адаптивность** - легко масштабируется под разные экраны
4. **Intersection Observer API** - стандарт для infinite scroll, экономит ресурсы
5. **Переиспользование кода** - используем существующие сервисы лайков

### Недостатки и риски:
1. **Сложность паттерна** - нужно правильно расставлять `grid-row: span 2`
2. **Производительность** - при >100 элементов нужен virtual scrolling (отложим)
3. **Мобильная адаптация** - на узких экранах может быть тесно

## 📐 Структура макета

```
Паттерн A (строки 0-1):
┌────────┬─────┬─────┐
│        │  1  │  2  │
│  BIG   ├─────┼─────┤
│   0    │  3  │  4  │
└────────┴─────┴─────┘

Паттерн B (строки 2-3):
┌─────┬─────┬────────┐
│  5  │  6  │        │
├─────┼─────┤  BIG   │
│  7  │  8  │   9    │
└─────┴─────┴────────┘

Паттерн A повторяется...
```

**Алгоритм расстановки:**
- Каждые 5 элементов = 1 паттерн (2 строки)
- Элементы 0, 5, 10, 15... = большие (span 2 rows)
- Четные паттерны (0, 2, 4...) - BIG слева
- Нечетные паттерны (1, 3, 5...) - BIG справа

## 🎨 CSS Решение для чередующихся паттернов

**Вариант 1: nth-child (рекомендую)**
```css
/* Каждые 5 элементов - один паттерн */
.feed-item:nth-child(10n+1) { grid-row: span 2; } /* 1, 11, 21... */
.feed-item:nth-child(10n+6) { grid-column: 3; grid-row: span 2; } /* 6, 16, 26... */
```

**Вариант 2: JavaScript классы**
При рендере добавляем классы `.feed-item-large-left` и `.feed-item-large-right`

## 🛡️ Защита архитектурного решения

### Почему CSS Grid, а не Masonry/Flexbox?

**1. Производительность**
- CSS Grid - нативный, аппаратно ускоряемый
- Masonry библиотеки (типа Masonry.js) требуют JS-вычислений при каждом resize
- Flexbox не подходит для двумерных grid'ов

**2. Простота**
- Grid - декларативный CSS, легко читать и поддерживать
- Альтернативы требуют сложную логику позиционирования в JS

**3. Telegram Mini App ограничения**
- Минимум зависимостей (размер бандла)
- Работа на слабых устройствах
- Grid поддерживается всеми браузерами Telegram

### Почему Intersection Observer?

**1. Эффективность**
- Не требует event listeners на scroll (экономия CPU)
- Браузер сам оптимизирует проверки
- Батарея мобильного устройства

**2. Стандарт**
- Нативный API, нет зависимостей
- Поддержка во всех современных браузерах

**3. Простота**
```typescript
const observer = new IntersectionObserver(
  (entries) => {
    if (entries[0].isIntersecting) loadMore();
  },
  { threshold: 0.5 }
);
observer.observe(lastElement);
```

### Альтернативы и почему НЕ выбрали:

**❌ Virtual Scrolling (react-window, virtuoso)**
- Сложность: высокая
- Оверкилл для начальной версии
- Усложняет CSS layout
- ✅ Можно добавить позже если >500 элементов

**❌ Masonry.js библиотеки**
- Зависимость: +20-40kb
- JS-вычисления позиций
- Сложнее поддержка
- ✅ Grid справится

**❌ Flexbox с колонками**
- Не подходит для точного контроля позиций
- Сложно сделать чередующиеся паттерны
- ✅ Grid - правильный инструмент
