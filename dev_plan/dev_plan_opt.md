# 🚀 План Оптимизации FastVLM: Разбиение метода analyze на 3 независимых метода

## 📋 Описание Задачи

**Текущая проблема**: Метод `analyze()` в `fastvlm-server/server.py` выполняет все операции последовательно:
1. Подготовка фото (сжатие)
2. Технический анализ (6 промптов последовательно) 
3. Создание ответа стилиста (Gemini)

**Цель**: Разбить на 3 независимых метода для параллельного выполнения и лучшего UX:
- Методы 1-2 запускаются сразу после создания фото (пока пользователь выбирает тему)
- Метод 3 вызывается только после выбора темы пользователем

## 🏗️ Архитектура Решения

### 🔧 **Метод 1: prepare_image() - Подготовка изображения**
- **Вход**: `image_base64` (сырое фото)
- **Выход**: `processed_image_base64` (обработанное фото)
- **Операции**:
  - Background removal через rembg (CPU)
  - Сжатие до оптимальных размеров
  - Оптимизация качества для анализа

### 🔧 **Метод 2: analyze_technical() - Технический анализ**
- **Вход**: `processed_image_base64`
- **Выход**: `technical_results` (6 параллельных анализов)
- **Операции**:
  - Параллельный запуск 6 промптов FastVLM
  - Person analysis, Clothing, Legs, Shoes, Accessories_head, Accessories_hand
  - Сбор результатов в структурированный формат

### 🔧 **Метод 3: create_stylist_response() - Ответ стилиста**
- **Вход**: `technical_results`, `topic` (тема от пользователя)
- **Выход**: `stylist_response` (креативный ответ)
- **Операции**:
  - Только формирование ответа через Gemini/Ollama
  - Использует готовые технические данные
