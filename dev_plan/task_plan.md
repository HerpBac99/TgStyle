# 🗄️ План внедрения базы данных в TgStyle

## 🎯 Цель проекта
Интеграция PostgreSQL + Redis в Telegram Mini App TgStyle для хранения пользователей, истории анализов, подписок и социальных функций.

## 📊 Текущее состояние

### ✅ Уже готово:
- **База данных**: PostgreSQL + Redis через Docker
- **Схема**: Prisma schema.prisma с моделями User, HistoryItem, Rating, Comment, Notification  
- **Подключение**: Prisma клиент инициализирован в server.js
- **Инфраструктура**: Docker контейнеры настроены и работают
- **Система подписок**: Поля в БД уже предусмотрены (analysesCount, subscriptionType)

### ❌ Требует интеграции:
- **Auth API**: Не создает пользователей в PostgreSQL
- **Analyze API**: Не сохраняет результаты в БД
- **История**: Хранится только в localStorage клиента
- **Подписки**: Нет проверки лимитов и управления
- **Социальные функции**: Rating, Comments, Notifications не реализованы

## 📋 Детальный план интеграции

### **ЭТАП 1: Интеграция авторизации** 🔐
**Файл**: `server/src/api/auth.js`

#### Задачи:
1. **Создание/поиск пользователя в PostgreSQL**
   - Поиск по `telegramId` 
   - Создание нового пользователя при первом входе
   - Обновление данных при повторном входе

2. **Обновление профиля пользователя**
   - Синхронизация `firstName`, `lastName`, `username`
   - Обновление `avatarUrl` из Telegram
   - Обновление `updatedAt` timestamp

3. **Проверка подписки**
   - Проверка активности подписки (`subscriptionEndDate`)
   - Проверка weekly лимитов (`analysesCount`, `weeklyResetDate`)
   - Автоматический reset еженедельного счетчика

4. **Возврат полных данных**
   - Возврат пользователя с информацией о подписке
   - Возврат доступных анализов в неделю
   - Возврат статистики (totalAnalyses)

#### Структура ответа:
```json
{
  "success": true,
  "user": {
    "id": 123,
    "telegramId": 987654321,
    "firstName": "John",
    "lastName": "Doe", 
    "username": "johndoe",
    "avatarUrl": "https://...",
    "subscription": {
      "type": "free|premium",
      "analysesLeft": 3,
      "totalAnalyses": 15,
      "weeklyResetDate": "2024-01-01T00:00:00Z",
      "subscriptionEndDate": null
    }
  }
}
```

### **ЭТАП 2: Интеграция анализа изображений** 🖼️  
**Файл**: `server/src/api/analyze.js`

#### Задачи:
1. **Проверка лимитов анализа**
   - Проверка `analysesCount` для free пользователей
   - Проверка активности подписки Premium
   - Возврат ошибки при превышении лимитов

2. **Сохранение результатов анализа**
   - Создание записи в `HistoryItem`
   - Сохранение `photoData` (base64 изображения)
   - Сохранение `technicalAnalysis` (результат FastVLM)
   - Установка `isPublic` статуса

3. **Обновление счетчиков пользователя**
   - Уменьшение `analysesCount` для free users
   - Увеличение `totalAnalyses`
   - Проверка и обновление `weeklyResetDate`

4. **Graceful fallback**
   - Работа без БД при недоступности
   - Логирование ошибок БД
   - Возврат результата анализа даже при ошибках сохранения

#### Логика проверки лимитов:
```javascript
// Для Premium пользователей - безлимитно
if (user.subscriptionType === 'premium' && user.subscriptionEndDate > new Date()) {
  // Unlimited analysis
}

// Для Free пользователей - проверка weekly лимитов
if (user.subscriptionType === 'free') {
  if (user.analysesCount <= 0) {
    return { error: 'Weekly analysis limit reached' };
  }
}
```

### **ЭТАП 3: API для управления историей** 📚
**Новые файлы**: `server/src/api/history.js`, `server/routes/history.js`

#### Новые endpoints:

##### `GET /api/history`
- Получение истории анализов пользователя
- Пагинация (limit, offset)
- Фильтрация по дате
- Сортировка по createdAt DESC

##### `GET /api/history/:id`
- Получение конкретного элемента истории
- Проверка прав доступа (владелец или isPublic)
- Возврат с комментариями и рейтингами

##### `PUT /api/history/:id`
- Обновление описания анализа (`analysisText`)
- Изменение видимости (`isPublic`)
- Валидация прав доступа

##### `DELETE /api/history/:id`
- Мягкое удаление элемента
- Проверка прав доступа (только владелец)
- Каскадное удаление связанных комментариев/рейтингов

##### `GET /api/history/public` (будущее)
- Публичная лента анализов
- Фильтрация и поиск
- Пагинация

#### Структура ответа истории:

##### `POST /api/subscription/reset-weekly`
- Административный сброс weekly лимитов
- Проверка `weeklyResetDate`
- Сброс `analysesCount` до 3 для free users

##### `GET /api/subscription/stats`
- Статистика использования
- График анализов по дням/неделям
- Сравнение с другими пользователями

#### Weekly Reset логика:
```javascript
// Автоматический сброс каждый понедельник
function checkWeeklyReset(user) {
  const now = new Date();
  const resetDate = new Date(user.weeklyResetDate);
  
  if (now > resetDate) {
    // Сброс счетчика
    user.analysesCount = 3;
    user.weeklyResetDate = getNextMondayDate();
    return true;
  }
  return false;
}
```
