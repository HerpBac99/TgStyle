# 🚀 План Развития Проекта TgStyle

## 🔥 НОВАЯ ФУНКЦИОНАЛЬНОСТЬ: Система Оценок и Комментариев

### 🎯 Цель проекта
Добавить социальную функциональность в TgStyle, где пользователи смогут:
- Оценивать чужие образы и анализы ИИ (лайки/дизлайки)
- Писать комментарии к историям других пользователей
- Просматривать публичные истории с оценками и комментариями
- Перенести хранение данных из localStorage в PostgreSQL базу данных

### 📊 Техническое задание

#### Архитектура решения
- **База данных**: PostgreSQL для хранения пользователей, историй, комментариев, оценок
- **Backend**: Node.js + Sequelize ORM для работы с PostgreSQL
- **Frontend**: Обновление TypeScript типов и добавление новых компонентов
- **Миграция**: Перенос существующих данных из localStorage в базу

#### Схема базы данных

**users** - Пользователи Telegram
```sql
CREATE TABLE users (
  id SERIAL PRIMARY KEY,
  telegram_id BIGINT UNIQUE NOT NULL,
  first_name VARCHAR(255) NOT NULL,
  last_name VARCHAR(255),
  username VARCHAR(255),
  avatar_url TEXT,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  is_active BOOLEAN DEFAULT true
);
```

**history_items** - История анализов (перенос из localStorage)
```sql
CREATE TABLE history_items (
  id SERIAL PRIMARY KEY,
  user_id INTEGER REFERENCES users(id) ON DELETE CASCADE,
  photo_data TEXT NOT NULL, -- base64 encoded image
  analysis_text TEXT,
  source_type VARCHAR(50) DEFAULT 'photo', -- 'photo' | 'pinterest'
  is_public BOOLEAN DEFAULT true,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  classification_class VARCHAR(255),
  classification_confidence VARCHAR(50),
  ai_model_used VARCHAR(100),
  fastvlm_used BOOLEAN DEFAULT false
);
```

**ratings** - Оценки постов
```sql
CREATE TABLE ratings (
  id SERIAL PRIMARY KEY,
  user_id INTEGER REFERENCES users(id) ON DELETE CASCADE,
  history_item_id INTEGER REFERENCES history_items(id) ON DELETE CASCADE,
  rating_type VARCHAR(20) NOT NULL, -- 'like' | 'dislike'
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  UNIQUE(user_id, history_item_id)
);
```

**comments** - Комментарии к постам
```sql
CREATE TABLE comments (
  id SERIAL PRIMARY KEY,
  user_id INTEGER REFERENCES users(id) ON DELETE CASCADE,
  history_item_id INTEGER REFERENCES history_items(id) ON DELETE CASCADE,
  content TEXT NOT NULL,
  parent_comment_id INTEGER REFERENCES comments(id) ON DELETE CASCADE, -- вложенные комментарии
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  is_deleted BOOLEAN DEFAULT false
);
```

**notifications** - Уведомления пользователей
```sql
CREATE TABLE notifications (
  id SERIAL PRIMARY KEY,
  user_id INTEGER REFERENCES users(id) ON DELETE CASCADE,
  type VARCHAR(50) NOT NULL, -- 'comment' | 'rating' | 'reply'
  message TEXT NOT NULL,
  related_user_id INTEGER REFERENCES users(id),
  related_history_item_id INTEGER REFERENCES history_items(id),
  related_comment_id INTEGER REFERENCES comments(id),
  is_read BOOLEAN DEFAULT false,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

#### API Эндпоинты

**Комментарии:**
- `GET /api/history/:id/comments` - Получить комментарии к посту
- `POST /api/history/:id/comments` - Добавить комментарий
- `PUT /api/comments/:id` - Редактировать комментарий
- `DELETE /api/comments/:id` - Удалить комментарий
- `POST /api/comments/:id/reply` - Ответить на комментарий

**Оценки:**
- `POST /api/history/:id/rate` - Поставить оценку (like/dislike)
- `DELETE /api/history/:id/rate` - Убрать оценку
- `GET /api/history/:id/rating` - Получить рейтинг поста

**История:**
- `GET /api/history/public` - Получить публичные посты для ленты
- `GET /api/history/:id` - Получить детали поста
- `PUT /api/history/:id/visibility` - Изменить видимость поста

**Уведомления:**
- `GET /api/notifications` - Получить уведомления пользователя
- `POST /api/notifications/:id/read` - Отметить уведомление прочитанным

#### Риски и решения

**Риск 1: Потеря данных при миграции**
- Решение: Создать backup всех данных перед миграцией
- Тестировать миграцию на staging окружении

**Риск 2: Производительность при росте базы**
- Решение: Добавить индексы, кэширование (Redis), пагинацию
- Оптимизировать запросы, добавить rate limiting

**Риск 3: Спам и токсичное поведение**
- Решение: Rate limiting, модерация контента, CAPTCHA
- Возможность блокировки пользователей

**Риск 4: Конфиденциальность данных**
- Решение: Шифрование чувствительных данных, GDPR compliance
- Анонимизация данных в аналитике
